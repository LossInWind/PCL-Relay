# PCL Relay 2.5.21

Fix the confirmed OpenCode custom-provider image capability mismatch and make
recognized Chat Completions upstream errors actionable. No OpenCodex code changes.

- API connection information retains generic OpenAI-compatible fields and adds an
  optional current OpenCode V2 configuration fragment. Merge, do not replace,
  existing configuration. Only GLM-5.2 and DeepSeek-V4-Pro receive verified
  text-only capabilities; unknown models are disabled in the new template pending
  independent validation. Existing local unknown models are not disabled.
- Model rows explain the dated evidence and unknown capabilities. Tool declarations
  and reasoning settings are retained. High request acceptance is not proof of
  reasoning quality. Context sizes and prices are not guessed.
- Chat errors preserve HTTP status and Relay request ID. Recognized image-input
  rejection is translated to a clear explanation. Error bodies are bounded and
  fail closed: arbitrary upstream prose can contain private request content and
  is not copied to clients or logs. Other HTTP categories receive safe explanations.
- Streaming bytes and request bodies are unchanged. No retry-after-output,
  fabricated completion, forced tool call or injected continuation was introduced.
- Kimi's normal stop without a tool call is distinct from a broken stream. Preserve
  the original conversation and use a reviewed handoff with bounded tasks; no
  automatic rewriting/compaction of user sessions.

Validation: 252 Python tests pass, standalone Swift configuration-export assertions
pass, Swift release build passes. XCTest is unavailable in this host's CLT; the
standalone check is not represented as the entire Swift unit suite. Isolated
OpenCode 2.0.16 history reconstruction contains zero images for the two text models,
with all 12 tools and reasoning_effort=high preserved. The original OpenCode config
was backed up and only these two capability declarations changed. Original sessions
and credentials were not edited.

Source: https://opencode.ai/v2/docs/models (capabilities and fallback assumptions).
Deployment must distinguish installed resources from running gateways. No active
model connection may be killed merely to activate this release.
