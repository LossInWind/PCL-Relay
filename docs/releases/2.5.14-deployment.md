# 2.5.14 deployment evidence — 2026-09-09

Release build: `2d839e31c04d999de9055ffdc373f2e9b76fd594`.
OpenCodex source is the exact upstream 2.48.0 tree. See
`../opencodex-2.48.0-upgrade.md` for upstream provenance and regression results.

## Observed upgrade failures

- The old GUI's GitHub API request returned HTTP 403 (rate limit).
  2.5.14 adds validated public release-metadata fallback.
- Registration alone did not establish update peers; the upgrade count was zero.
  The existing registration action connected reachable receivers.
- Old Linux receivers validated new bundles against the old running updater's
  OpenCodex pin. 2.5.14 validates the verified bundle's literal pin instead.
- Kai's old receiver made overlapping slow GitHub downloads. Its control process
  was stopped for a bounded bootstrap migration, without stopping its model
  process. GitHub exceeded the bootstrap deadline; the same verified macOS
  release was then transferred from the initiating Mac.
- A6000 could not resolve GitHub and had no configured peer-cache source. The
  verified Linux release was transferred through its registered SSH target.
- A6000's existing systemctl compatibility shim rejected quoted ExecStart tokens.
  The service definition was normalized to unquoted literal arguments. Its old
  control process was not owned by the shim, so that exact control PID was
  gracefully stopped before starting the registered control service. No model
  process was stopped in this migration.

## Remaining gates

- Do not describe staged OpenCodex resources as a running upgrade. The local
  Mac and Kai need an idle activation window. A6000 needs a verified upstream
  detached-runtime handoff that does not perform stop/restore on user history.
- Kai's GUI bundle is installed; a running old GUI may still need reopening.
- The old slow-download/concurrent-offer behavior was recovered operationally;
  this release does not claim a new persistent, single-flight update job system.
- Real isolated requests passed for official GPT and all four PCL models,
  including streaming/compaction/tools/continuation; this is not a claim that
  every remote desktop and native child-agent workflow was individually retested.
